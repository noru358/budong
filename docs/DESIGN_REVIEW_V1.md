# 개인 V1 디자인 검토

기준일: **2026-10-02 (Asia/Seoul)**. UX와 디자인을 병렬 작업하고, UX는 화면 구조·입력 동선을, 디자인은 `web/styles.css`의 표현을 담당했다.

## 검토 범위

클라우드의 실제 Chromium에서 개인 V1을 열어 검토했다. 초기 화면은 기존 분석 데스크톱·390px 홈 캡처로 확인했고, 개선 후 1280px·390px·320px 화면을 직접 재현했다. 사용자가 띄운 Mac 화면은 이 환경에 연결된 증거가 없으므로 이번 검토 대상에 포함하지 않았다.

기존 녹색·크림색 표현과 공식 용어·계산 의미를 유지했다. 금액을 쉽게 비교하고, 근거와 가정을 읽으며, 모바일에서 입력하기 위한 개선에 집중했다. 수익률에 따라 투자 우열을 색이나 점수로 판정하지 않는다.

## 문제와 적용한 개선

| 실제 화면의 문제 | 개선 |
|---|---|
| 금액과 비율이 좌측 정렬되어 행 사이 수치 비교가 어려움 | 금액 입력·지표에 고정폭 숫자 사용. Finance 표의 숫자 오른쪽 정렬, 시간표의 날짜·항목은 왼쪽 정렬 |
| 모바일 비교표를 가로로 이동하면 지표 맥락이 사라짐 | Finance 표 첫 열을 모바일에서 유지. 모바일 좌우 이동 안내와 키보드로 접근할 수 있는 표 영역을 UX와 연결. 표 안에서 가로 이동하고 페이지 전체는 넘치지 않게 처리 |
| 긴 물건·구역 이름이 좁은 카드에서 어색하게 분절됨 | 단어 경계 우선 줄바꿈, 긴 텍스트는 안전하게 접기. 구역 제목의 줄 균형, 긴 비교 헤더 여러 줄 표시 |
| 작은 보조 버튼과 컨트롤·원문 링크가 터치하기 어려움 | 버튼·입력·선택·원문 링크 영역 최소 높이 44px |
| 보조문구와 placeholder가 화면에서 약하게 보임 | 보조문구 5.31:1, placeholder 5.06:1의 실제 배경 대비. 기존 글자 크기 위계 유지 |
| 접힌 상세 항목의 키보드 포커스 표시가 부족함 | `summary`를 포함해 명확한 포커스 테두리, 배경 대비 4.24:1 |
| 입력 과정에서 단계 구분과 지급 일정 행이 붙어 보임 | 단계 사이 구분선·여백, 지급 일정의 라벨·입력 간격 개선 |
| 입력 오류와 만원 단위 금액을 다시 확인하기 어려움 | UX의 개별 오류에 높은 대비 글자·입력 테두리, 만원→원 보조값을 숫자 입력 아래 오른쪽 정렬 |
| 320px에서 그리드 최소 너비와 긴 텍스트가 넘칠 가능성 | 카드 최소 너비와 KPI 열 크기에 안전한 축소 규칙, 작은 화면의 좌우 여백 조정 |

## 확인 결과

- 기존 브라우저 smoke **PASS**: 실제 구역 검색·원문, 입력·계산·저장·복원·비교·내보내기, 미확인값, 최근 구역, 모바일, 지도 가드, 삭제. 페이지 오류 없음.
- 별도 격리 프로필의 실제 Chromium 시각 검토: **1280px·390px·320px 홈/검색/분석/입력**, 390px 공식 근거 화면에서 페이지 가로 넘침 없음.
- 숫자 입력 오른쪽 정렬, 키보드로 이동한 상세 항목의 포커스 표시 확인.
- Finance 표 숫자 오른쪽 정렬과 모바일 첫 열 유지 확인. 긴 비교 물건 이름의 헤더 줄바꿈을 화면으로 확인했다.
- 개별 오류의 2px 테두리·고대비 오류문구, `54000만원 → 540,000,000원` 보조값 오른쪽 정렬을 실제 입력 화면에서 확인했다. 오류가 있는 입력 화면도 가로 넘침 없음.
- 전체 접근성 감사와 모든 Mac·iPhone 기기 검증은 이번 검토 범위에 포함하지 않는다. 검증은 가상 물건 입력으로 수행했으며 실제 매물·API 성공·경계 연결을 의미하지 않는다.
