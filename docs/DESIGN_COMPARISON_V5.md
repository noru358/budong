# V5 지도 구역 탐색: 재개발닷컴 직접 관찰과 적용

조사일: 2026-10-03. 기준 버전: `2a6b050`. 공개 데스크톱 화면을 Safari에서 직접 열고, 실제 구역 라벨·사업종류 필터·축소 버튼을 조작했다. 로그인, 소유자 인증, 관심 등록, 거래 행위는 하지 않았다. 경쟁사의 도형·데이터·아이콘·지도 자산을 budong에 복사하지 않았다.

## 먼저 인정할 기능의 차이

기준 버전의 budong은 44개 구역의 사업현황 목록과 배경지도, 사용자 참고 위치·경계 가져오기를 제공한다. **44개 표준 구역에 자동 연결된 실제 좌표·구역 경계는 0개였다.** 따라서 그 시점에는 지도를 열어 구역을 공간적으로 탐색하는 핵심 작업이 성립하지 않았다. 화면 구성·드래그·줌·입력 계산이 동작한다는 이유로 이 작업을 완성했다고 평가할 수 없다.

이번 변경은 공공 출처에서 확보한 행정 참고경계를 구역 ID에 연결하는 데이터 작업과, 그 경계를 알아보고 선택하는 인터페이스 작업을 함께 진행한다. 확보 건수·정책상 표시 가능 건수·실제로 표시된 고유 구역 수는 각각 검증해야 한다. 최신 고시 경계와 원문 대조가 끝난 법적 경계의 수로 바꾸어 표현하지 않는다. 원자료는 개인 로컬 이용 조건으로 Git에서 제외하며, UI·출처 라벨·어댑터만 저장소에 포함한다.

## 직접 확인한 화면과 조작

출처는 [재개발닷컴 공개 홈](https://jaegebal.com/), 지도 라벨 클릭으로 열린 [마포로1-23 상세](https://jaegebal.com/develops/5503)다. 아래는 화면·접근성 상태에서 확인한 사실이며, 데이터 정확성을 별도로 검증한 결과는 아니다.

| 상세 밀도 | 선택 패널에 실거래·진행현황·자료실·구역정보 등의 탭, 거래 그래프·표, 추진위승인 날짜가 보임 | budong은 기존 원문 근거·관찰 단계·내 물건 계산 흐름을 보존한다. 주변 실거래를 검증된 구역 내부 거래로 바꾸지 않는다 |

스크린샷은 조사 세션의 CUA 도구 출력에 남겼다: 초기 자치구 군집, 확대 동별 군집, 개별 구역, 선택 상세, 사업종류 필터, 축소 후 다구역 화면. 파일로 저장하는 별도 캡처는 `work/design-v5/`에 모으며, 실제 파일이 없는 화면에 파일 경로나 이미지 출처를 붙이지 않는다.

## 관찰의 한계

- 일부 화면 변화가 사용자 조작과 겹쳤다. 동별 군집에서 마포 상세 줌으로 이동한 과정은 우리 조작의 결과라고 주장하지 않는다.
- **hover 반응은 직접 확인하지 못했다.** 이번 budong의 hover는 구역을 누를 수 있음을 알리는 자체 설계다.
- 경쟁사에서는 이름 라벨 클릭→상세 연결을 확인했다. 도형 면 클릭, 검색 결과 목록 클릭→지도 선택, 키보드 선택, 모바일 반응은 이번 조사에서 검증하지 않았다.
- 축척 3km·1km·50m·100m의 화면을 확인했지만, 경쟁사 내부 줌 레벨·전환 임계값·충돌 제거 알고리즘은 알 수 없다. 아래 줌 임계값은 budong 자체 결정이다.
- 지도에 보이는 경쟁사 경계의 법적 최신성·재이용 조건·권리 판정 정확성은 이 디자인 조사로 확인하지 않았다.

## 구현 계약과 선택 이유

지도 렌더러는 경계를 검증하고 아래 클래스와 상태를 전달한다. CSS는 데이터의 출처·권한을 판정하거나 경계를 생성하지 않는다.

| 클래스/상태 | 표현 |
| --- | --- |
| `zone-boundary` | 기본 외곽 2.5px, 면 불투명도 16%. 사업색은 렌더러의 `color`/`fillColor`를 유지 |
| `zone-boundary--reference` | 행정 참고경계 점선. 최신 법적 경계로 오인시키지 않음 |
| `zone-boundary--user` | 사용자 참고경계 짧은 점선. 사용자 위치 점과도 구분 |
| `is-hovered` | 외곽 3.5px·면 24%. budong 자체 설계 |
| `is-selected`/키보드 focus | 짙은 외곽 4px·면 25%·흰 대비 효과. 색만으로 선택을 설명하지 않음 |
| `zone-label` | 사업색 이름/기존 단계/경계 종류 3줄. 데스크톱 최대 220px, 작은 화면 최대 180px, 긴 이름은 줄바꿈 |
| `zone-label--redevelopment/reconstruction/other` | 파랑 `#2563eb`/보라 `#7c3aed`/청록 `#087f8c`. 수익·위험·권리 검증 등급을 뜻하지 않음 |
| `zone-label--selected` | 검정 외곽과 흰 halo. 목록 선택과 동시에 유지 |
| `zone-cluster-name/count` | 구명+실제 경계 연결 구역 수. 최소 72×58px 클릭 표적. 선택된 구역을 포함한 군집은 `is-selected`의 검정 외곽으로 표시 |
| `zone-legend` | 사업색 범례와 행정 참고 점선 설명. 출처·이용조건 링크와 지도 제공자 표기를 가리지 않음 |

렌더러의 budong 자체 임계값: 줌 12 이하 자치구별 군집, 줌 13에서 선택 구역 라벨, 줌 14 이상 상시 개별 라벨. 낮은 줌에서는 선택 라벨을 숨기고 선택 구역을 포함한 군집을 강조한다. 큰 선택 라벨이 군집 클릭을 가리는 문제를 통합 QA에서 발견하여 바꾼 규칙이다. 선택 구역 ID 자체는 유지한다. 라벨 단계는 기존 정보몽땅 관찰값이고, 행정 참고경계의 자료기준일과 별도다. 군집에는 사용자 점을 합산하지 않는다.

## 완료 판단에 사용할 검증 항목

경계 데이터 연결 전에는 CSS만 검토 가능하다. 지도 기능의 완료 보고는 아래 실제 통합 검증 결과를 함께 갖추어야 한다.

1. 실제 공공 자료를 읽은 경계 수, 고유 구역 수, 표시에서 제외된 구역 ID와 이유를 확인한다.
2. 개인 로컬 모드에서 허용된 경계를 표시하고, 상업·공개 환경에서는 정책상 허용되지 않는 원자료가 노출되지 않는지 확인한다.
3. 자치구 군집 클릭→경계 범위 확대→개별 라벨→구역 선택→목록/요약→기존 상세 이동이 연결되는지 확인한다.
4. hover·키보드·줌 변경 뒤 선택 상태, 행정 참고 점선, 긴 구역명의 라벨, 좁은 화면에서 범례·출처와 줌 버튼의 겹침을 확인한다.
5. 자동화 UI 검증은 외부 OSM 타일을 차단하고 로컬 대체 타일을 쓴다. 실지도 화면은 별도의 수동 공개 초기 뷰에서 확인한다.

그 검증 전에는 '지도 탐색 완료'나 임의 완성도 비율을 붙이지 않는다. 데이터 확대가 행정 참고경계 연결을 뜻하며, 원문 대조가 완료된 최신 법적 경계 연결을 뜻하지 않는다는 한계는 결과 보고에도 남긴다.

## 실제 통합 화면에서 확인한 결과

2026-10-03 Safari의 개인 로컬 지도 화면에서 **경계 42개·전체 구역 44개·사용자 위치 0개**를 확인했다. 마포로1구역 제25지구와 신월7동 1구역은 목록에 `위치 미연결`로 남아 있다. 나머지 경계의 라벨과 선택 요약은 `서울시 행정 참고경계`, `최신 정비고시 경계·권리 판단은 원문 대조가 필요합니다`라고 표시한다. 경계 원자료는 개발·데이터 담당자가 확보·연결했으며 디자인 담당자가 경쟁사에서 복사한 도형이 아니다.

실화면에서 개포주공6,7단지의 선택된 검정 점선 외곽·보라 면·사업단계·근거종류와 인근 개포주공5단지 라벨을 확인했다. 목록에서 상도15를 직접 선택하여 URL 구역 ID, 목록 선택, 요약, 지도 범위와 검정 경계 강조가 함께 변경되는 것을 확인했다. 상도14와 상도15의 라벨이 서로 구분되고, 이름은 가로로 읽힌다.

첫 통합 화면에서 발견한 두 문제를 수정했다. 절대배치 tooltip이 32px로 수축해 구역명이 한 글자씩 세로로 늘어났으므로 `width:max-content`와 최소 너비를 주고 긴 이름을 두 줄로 제한했다. 전체 구역명은 목록과 경계의 접근성 이름에도 남긴다. 범례와 출처가 지도 하단에 겹쳤으므로 범례를 지도 도구행 아래, 출처를 상태행 아래의 실제 행으로 옮겼다. 수정한 Safari 실화면에서 두 문제가 해소된 것을 확인했다.

390px 모바일 캡처에서도 가로 라벨과 구분된 범례·출처를 확인했다. 상단 구역 라벨을 긴 조작 안내가 가리는 문제는 모바일에서 확대 단계 배지만 남겨 해결한다. 출처 글자는 모바일에서 9px로 유지한다. 통합 QA에서 저배율 선택 라벨이 군집을 가리는 문제를 발견해, 저배율에서는 라벨 대신 해당 군집을 강조하도록 계약을 변경했다. 키보드·hover·정책 노출의 동작 검증은 개발 담당자의 통합 QA 결과와 함께 보고한다.
