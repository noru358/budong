# 탐색·지도 역할 분리와 조작 수정 — 2026-10-03

사용자가 ‘구역 탐색과 지도가 거의 같고 지도가 작동하지 않는다’고 지적한 뒤 현재 사파리 화면과 코드를 함께 확인했다. V3는 두 탭에서 같은 explorer를 렌더했고 지도 화면도 목록 너비만 바꿨다. 휠 확대를 명시적으로 꺼두었으며, 선택 요약이 지도 위에 겹쳐 확대 버튼을 가렸다. 검증된 위치 자료가 없는데도 구역 목록 선택과 실제 지도 이동을 분명하게 구별하지 않았다.

## 수정 결과

| 화면 | 역할·동작 |
|---|---|
| 구역 탐색 | 구역명·주소·자치구·유형으로 목록을 검색하고 단계·근거 요약을 읽는다. 지도 엔진을 올리지 않는다. 선택 맥락을 유지하며 ‘지도 열기’로 전환한다. |
| 지도 | 별도 지도 작업면·구역 선택창·위치 연결 상태. 휠/더하기·빼기 확대·드래그/방향키 이동. 지도에 표시된 구역 필터, 저장한 위치/경계로 이동, 서울 전체 보기. |

선택 정보는 지도 캔버스 밖의 사이드바로 옮겼다. 확대 버튼은 지도 우상단에 놓고 상단 도구·배경지도 연결 상태·축척·확대 단계·출처 표시를 분리했다. 모바일은 지도를 먼저 보여주고 아래에서 구역을 선택한다. 확대 버튼은 1440/768/390/320px에서 다른 요소에 가려지지 않는다.

구역 선택에 연결된 사용자 위치 또는 검토 경계가 있으면 실제 좌표/범위로 이동한다. 없는 구역은 ‘위치 미연결’로 표시하며 기존 지도 중심을 임의 주소 좌표로 바꾸지 않는다. 직접 위치 지정은 패널을 잠시 닫고 지도를 누르게 한 뒤 좌표를 채운 패널을 다시 보여준다. Escape 취소와 닫기 동작도 제공한다. 화면 전환·검색으로 지도 컴포넌트를 다시 만들 때 현재 지도 중심·확대 수준을 유지한다. 전체 브라우저 새로고침이나 다른 브라우저로 해당 화면 상태를 동기화하는 기능은 아니다.

배경 타일 실패는 위치/경계 수집 상태와 별도의 연결 상태로 표시하며 ‘다시 연결’은 현재 화면의 타일만 재요청한다. 실패를 정상 연결로 덮어쓰지 않는다. 대량 타일 수집·새 주소 검색 서비스·임의 구역 좌표는 추가하지 않았다. 지도 해제 뒤 실행될 수 있는 resize callback을 차단하고 진행 중 이동을 정지해 화면 전환 중 Leaflet 오류를 수정했다.

## 검증

- Mac Node24 전체174테스트 통과, 실패/skip0.
- 격리 Chrome 전체 기존 물건 입력·계산·저장·비교·백업 동선과 새 지도 동선 통과.
- 새 지도 검증은 탐색의 지도 미생성/지도 별도 작업면, 더하기 버튼, 실제 wheel event, 드래그로 중심 변경, 지도 클릭 후 위치 폼 복귀, 저장한 위치 선택 후 정확한 중심 이동, 지도 표시 구역 필터, 화면 전환 뒤 중심/확대 유지, 확대 버튼의 실제 hit target, 타일 실패→재시도 성공을 확인했다.
- 화면1440/768/390/320px 가로 넘침 없음. 브라우저 page error0. 자동 테스트는 타일 응답/실패를 모의하고 외부 타일 요청0이다.
- 실제 사파리에서 온라인 OSM 배경지도 연결과 확대 버튼으로 11→12 단계 변경을 확인했다. 이후 사용자가 보고 있는 사파리 화면에서 확대16 상태도 관찰했다. 전체 Safari 자동 동선 테스트를 수행했다는 뜻은 아니다.

## 남은 위치 자료

현재 기본44구역의 검증된 좌표·공식 경계는 아직 앱 자료로 연결하지 않았다. 따라서 개인 위치·가져온 검토 경계가 없으면 ‘표시된 구역0·전체44’가 정확한 초기 상태다. 이 변경으로 44구역 위치 연결 완료나 공식 경계 확보를 주장하지 않는다. 부서별 다음 작업은 [현재 작업판](../PROJECT_DASHBOARD.md)의 동일5구역 필지·경계 연결을 따른다.
